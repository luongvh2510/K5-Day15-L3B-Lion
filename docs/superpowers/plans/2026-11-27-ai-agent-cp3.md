# Agent AI cho D2 (phần của Lương) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sửa công cụ kiểm cứng theo dữ liệu hiện tại (món chay suy ra từ thành phần), rồi thay bộ đọc chat mô phỏng bằng agent 2 phase gọi model thật, chạy được bằng `python run.py` (hội thoại nhiều lượt) và `python run.py eval` (mỗi câu thử một phiên), để nộp CP3.

**Architecture:** Các bước LLM là hàm thuần trong `codebase/llm_steps.py` (nhận tham số → gọi `call_model` → trả dict đúng schema). `codebase/core.py` là bộ điều phối 2 phase, giữ phiên trong dict bộ nhớ, gọi các bước LLM và công cụ kiểm cứng của Dũng trong `codebase/tools.py`. `codebase/agent.py` (cho eval) và `codebase/app.py` (CLI) chỉ là lớp mỏng gọi `core.py`. Sau CP3, Dũng thay dict bằng DB và mở API gọi vào `core.py` — không viết lại luồng.

**Tech Stack:** Python 3.10+, chỉ thư viện chuẩn (`json`, `re`, `urllib`, `unittest`). Model gọi qua `codebase/ai.py` theo `docs/connect-model.md`.

**Spec:** `spec.md` §4 (hình dạng, bảng Phase 1/Phase 2, ý định, các bước LLM, phòng thủ hai lớp), `docs/ba/01-nghiep-vu-va-quy-tac.md` (BR-xx), `docs/ba/05-AI-agent.md` §4 (schema đầu ra LLM), `eval/benchmark.csv`, `eval/metric_spec.yaml`.

**Cần Lương quyết trước Task 1:** nhà cung cấp model (`MODEL_PROVIDER` trong `.env`: `openai`, `anthropic`, `gemini`, `ollama`…) và `MODEL_NAME`.

### Task 4: Bộ điều phối 2 phase (`core.py`)

**Files:**
- Modify: `codebase/core.py`, `codebase/llm_steps.py`
- Create: `prompts/choose_restaurant.md`, `prompts/pick_items.md`, `prompts/route_message.md`
- Test: `tests/test_core.py`

**Interfaces:**
- Consumes: Task 0 (`list_restaurants`, `load_menu`, `safe_mains`, `feasibility`, `validate_cart`, `store_summary`, `shipping_fee`, `dish_exclusion`); các hàm Task 2–3.
- Produces (llm_steps):
  - `choose_restaurant(profile: dict, stores: list[store_summary(...)], tried: list[str]) -> {"store_id": str, "reason": str}`. Code gọi `store_summary` cho từng quán ứng viên trước, model chỉ chọn. Nếu mọi quán đều có `min_total` là `None` hoặc vượt quỹ thì code không gọi model, chuyển thẳng `CART_INFEASIBLE` với quán có nhiều món an toàn nhất.
  - `pick_items(members: list[Member], options: {tên: [{"id","name","price"}]}, budget: int, shipping: int, errors: list[str]) -> {"picks": [{"member": str, "item_id": str, "reason": str}]}`.
  - `route_message(text: str, profile: dict, cart: dict | None) -> {"intent": "CHANGE_ITEM" | "ADD_HARD" | "REMOVE_HARD" | "CHANGE_BUDGET" | "CHANGE_RESTAURANT" | "OTHER", "member": str | None, "detail": str, "amount": int | None, "tag": str | None}`.
- Produces (core) — phiên là dict:
  `Session = {"id": str, "status": "PROFILE_DRAFT" | "CART_VALID" | "CART_INFEASIBLE" | "FINALIZED", "profile": dict, "locked": bool, "shipping": int, "candidates": list[str] | None, "store_id": str | None, "tried": list[str], "cart": {"lines": [{"member","item_id","name","price","reason"}], "subtotal", "shipping", "total", "budget", "remaining", "excluded": {tên: {item_id: lý do}}, "built_by": "AI" | "FALLBACK"} | None, "infeasible": {"kind": "NO_SAFE_ITEM" | "OVER_BUDGET", "members": list[str], "min_total": int | None, "shortfall": int | None} | None, "messages": [{"role", "kind": "TEXT" | "QUESTION" | "REFUSAL" | "INFO", "text"}]}`. Tên trường theo `docs/ba/04` §2.5 ở mức có thể; Dũng ánh xạ sang `SessionState` khi làm API.
  - `start(chat_text: str, shipping: int | None = None, candidates: list[str] | None = None, budget: int | None = None) -> Session` — Phase 1 bước 1–2; `budget` (nếu có) ghi đè quỹ đọc từ chat.
  - `send(session: Session, text: str) -> Session` — `PROFILE_DRAFT`: trả lời câu hỏi mở đầu tiên qua `apply_answer` + `apply_changes(locked=False)`; các trạng thái giỏ: `route_message` rồi xử lý theo bảng ý định ở `spec.md` §4.
  - `confirm(session: Session) -> Session` — chỉ khi `can_confirm`; khoá rồi `_plan_cart`.
  - `finalize(session: Session) -> Session` — chỉ khi `CART_VALID`.
  - `render(session: Session) -> str` — chữ hiển thị cho CLI/eval: câu hỏi mở, hoặc giỏ (từng người, món, giá, tạm tính, ship, tổng, còn lại, món bị loại kèm lý do), hoặc thông báo bất khả thi có số tiền thiếu, hoặc lời từ chối.
